## 第1章 一笔没有银行参与的转账

### 1.1 先看完整故事

Alice 想给 Bob 转 100 元。

使用银行卡时，这件事很容易理解。银行先检查 Alice 的账户里有没有 100 元，再把 Alice 的余额减去 100，把 Bob 的余额增加 100。银行保存着唯一被认可的账本，也负责处理重复支付、伪造指令和账户纠纷。

现在拿掉银行。Alice 和 Bob 只通过互联网联系，周围还有许多互不认识的人。新的问题马上出现了：谁保存余额？谁判断 Alice 有没有这笔钱？Alice 能不能把同一笔钱同时转给 Bob 和 Carol？大家看到不同的交易顺序时，应该相信哪一个版本？

比特币给出的方案可以先压缩成下面这段话：

> Alice 用自己的私钥签署交易，把交易发给比特币网络。网络中的节点分别检查交易。矿工从有效交易中组织候选区块，并通过工作量证明竞争记账机会。某个候选区块胜出后，全节点再次独立检查它；符合规则的区块被接到当前账本后面，其他矿工继续在这个新区块之后工作。

这段话已经包含了整套系统。接下来的章节只是在逐一回答其中的问题：签名为什么可信，节点检查什么，矿工怎样竞争，区块怎样连接，以及不同版本出现时网络怎样继续。

先记住四类参与者。

| 参与者 | 主要工作 |
|---|---|
| 用户与钱包 | 生成密钥、组织交易、签名并发送交易 |
| 全节点 | 保存和检查账本，独立判断交易与区块是否符合规则 |
| 矿工 | 组织候选区块，投入算力竞争新区块的产生机会 |
| 矿池 | 在现实中协调大量矿机，把任务和收益集中管理 |

同一台电脑可以同时承担多个角色，但这些角色的职责需要分开理解。普通用户发送交易时不需要挖矿；矿工找到一个合格结果，也不能随意修改全节点执行的规则。

---

### 1.2 我们真正信任的是什么

生活中的货币依赖一套共同接受的记录方式。现金由防伪技术和法律体系支撑；银行卡余额由银行数据库记录；校园卡余额由学校的结算系统记录。我们相信这些数字，是因为背后存在可以维护记录、纠正错误并承担责任的机构。

中心机构的价值很直接。它能统一交易顺序，冻结可疑账户，撤销部分错误操作，也能在密码遗失时帮助恢复身份。现实中的大多数支付都适合采用这种方式。

区块链研究的是另一类问题：当参与者分散在世界各地，彼此缺少稳定信任关系，又希望共同维护一份记录时，能否让每个人都依据公开规则自行核查？

这里的目标是重新安排信任。它把信任拆开，分别放到密码学、公开规则、软件实现、经济激励和参与者的选择中。读者在后面会看到，交易所、钱包软件、网站入口和现实法律仍然会带来新的信任关系。

---

### 1.3 一种货币为什么会被接受

一套账本能够准确记录转账，还没有回答另一个问题：Bob 为什么愿意接受账本中的数字？

生活中的货币通常承担三项工作。它可以作为交换媒介，让人们用同一种东西买卖；可以作为计价单位，让商品有共同价格；也可以保存一部分价值，让今天获得的购买力留到以后使用。

人民币能够广泛承担这些工作，依靠国家法律、税收体系、银行网络、商业活动和公众长期形成的共同接受。校园卡余额只在学校范围内有用，因为学校负责记账，食堂和商店愿意接收，离开这个范围后用途会迅速缩小。

比特币走了另一条路。协议规定发行节奏和转账规则，分散节点共同维护账本，用户能够自行保管和跨网络转移。有人看重它的稀缺规则，有人看重开放结算，也有人只根据未来需求进行交易。这些需求汇合后形成市场价格。

稀缺只能说明供给受限，价值还需要需求。全世界可以有许多数量极少的数字文件，缺少用途、流动性和共同接受时，它们仍然很难交换。比特币的总量规则为稀缺提供条件，网络效应、实际用途、市场流动性和参与者预期共同影响价格。

价格也会反向变化。需求下降、监管环境改变、技术出现问题或市场流动性收缩时，同样的供给规则可以对应更低价格。协议能够规定怎样发行和转移，市场持续回答“有多少人愿意在什么价格接受”。

因此，理解加密货币需要同时看两层：账本怎样保证记录有效，人们为什么愿意为记录中的单位提供商品、服务或其他货币。

---

### 1.4 数字货币最难的一关：重复花费

一张纸币交给 Bob 后，Alice 手里就没有这张纸币了。数字文件却可以无限复制。一张图片发送给 Bob 后，Alice 的电脑里仍然保留原图。

因此，数字货币不能只是一份写着“价值 100 元”的文件。Alice 完全可以复制十份，分别发给十个人。真正需要保护的是一条规则：某份资金一旦在一笔有效交易中被使用，后续交易就不能再次使用它。

这就是双花问题。

假设 Alice 几乎同时发出两笔交易：一笔把同一份资金付给 Bob，另一笔付给 Carol。两笔交易都带有 Alice 的有效签名。签名只能证明两笔交易都由私钥持有者授权，无法单独决定哪笔交易先发生。

系统还需要一份大家可以核查的交易顺序。比特币把交易分批写入区块，再让区块按先后顺序连接。当前累计工作量最大的有效链，给出了网络此刻采用的记录版本。后续区块不断增加后，早先交易被改写的可能性会迅速降低。

这里的“当前”很重要。比特币没有中央数据库，也没有一位管理员按下“最终确认”按钮。节点通过接收消息和独立执行规则，逐渐在同一份有效历史上收敛。

---

### 1.5 开放网络为什么更难

在一个公司内部，可以提前登记服务器身份，并规定谁有投票权。公开网络允许任何人加入，一个人也能创建成千上万个网络身份。如果简单采用“一台电脑一票”，攻击者只需批量创建身份，就能伪装成多数。

这种行为叫作女巫攻击。它说明了一个基本事实：网络身份很便宜，不能直接用来衡量意见的分量。

比特币采用工作量证明，把产生新区块的机会与真实计算投入联系起来。每次哈希计算都像一次独立抽签，算力越高，每秒获得的抽签次数越多。找到合格结果的矿工只能提出一个候选答案；全节点仍会检查这个区块是否满足公开规则。

因此，“用算力投票”只是一种方便的简称。更准确的说法是：

> 矿工用工作量竞争出块机会，全节点用公开规则验收区块，累计工作量帮助节点在多个有效分支之间选择当前采用的历史。

算力可以影响哪个有效区块更快出现，却不能让一笔没有签名的交易变得合法，也不能让超额领取奖励的区块通过全节点检查。

---

### 1.6 比特币怎样拼起一份公开账本

比特币没有依赖某一项神奇技术。它把几种成熟工具组合成了一套能持续运行的系统。

数字签名负责授权。Alice 用私钥为交易生成签名，其他人用公钥检查签名。交易内容保持公开，私钥始终留在 Alice 手中。

哈希函数负责生成数据指纹。交易内容只要改变一点，哈希结果就会完全不同。区块通过哈希连接后，修改旧记录会让后续连接失效。

点对点网络负责传播。钱包只需把交易发送给几个相邻节点，节点验证后继续转发，消息便会逐步扩散。

区块负责排序。矿工把一批有效交易组织进候选区块，候选区块明确指向前一个区块，由此形成先后关系。

工作量证明负责竞争。许多矿工同时尝试哈希计算，找到合格结果的矿工传播完整区块。节点检查通过后，矿工开始在新区块之后组织下一轮候选区块。

激励负责维持参与。新区块允许矿工申领协议规定的区块补贴和本区块交易手续费。全节点会检查申领金额，矿工无法自行决定奖励数额。

后面的比特币部分会把这段过程完整走一遍。现在只需要形成全景图，不需要记住所有术语。

### 1.7 区块链解决问题的边界

区块链适合处理“多方需要共享记录，同时难以共同指定一个中心维护者”的场景。即使满足这个条件，区块链也会带来速度、成本、隐私和治理方面的代价。

它能证明某个私钥授权了一笔交易，也能为某段数据在大致时间范围内已经存在提供证据。区块时间戳受到协议允许范围和节点观察时间约束，不能当作精确到某一秒的公证时间。它也无法自动判断链外信息是真是假。例如，链上合约看到“货物已经送达”这条数据时，仍然需要某个人、设备或服务把现实信息带进系统。

它还能保证符合规则的记录很难被事后改写，却无法保证规则本身合理。一个有漏洞的智能合约可以被准确执行；一个设计失衡的金融协议也可能按照原定规则准确崩溃。

理解这些边界，能够帮助我们用工程问题看待区块链：参与者是谁，他们各自信任什么，数据从哪里来，错误发生后由谁承担，额外复杂度换来了什么。

### 本章小结 {#chapter-1-summary}

这一章只建立一幅总图。用户签署并发送交易，全节点检查规则，矿工组织候选区块并竞争出块，获胜区块经节点独立验收后接入当前账本，下一轮随即开始。

数字货币的核心困难是重复花费和交易排序。数字签名解决授权问题，区块与工作量证明帮助开放网络形成可核查的顺序。区块链降低了对单一记账机构的依赖，也引入了新的技术、经济与治理成本。

读到这里，应当能够回答四个问题：一种数字货币为什么会被接受，普通用户为什么不需要挖矿，签名为什么不能单独解决双花，以及矿工找到结果后为什么还要经过全节点检查。

## 第2章 密码学基础：只学理解交易所需的部分

### 2.1 本章要解决什么

密码学很深，完整学习需要数论、概率和专门的安全课程。这本书的目标更具体：看懂钱包怎样授权一笔交易，节点怎样检查授权，以及区块中的数据为什么难以悄悄修改。

我们会使用三个工具：哈希函数、公私钥和数字签名。RSA 的历史、椭圆曲线的完整推导以及具体签名算法的证明会放在进阶说明中，不占用主线。

本章继续使用同一个场景：Alice 想把一笔比特币转给 Bob。

---

### 2.2 哈希函数：数据的指纹

哈希函数接收任意长度的数据，输出固定长度的结果。比特币大量使用 SHA-256。下面是一个可以实际运行的例子：

```python
import hashlib

message = "hello".encode("utf-8")
print(hashlib.sha256(message).hexdigest())

# 输出：2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
```

同一份输入总会得到同一份输出。输入只改变一个字符，输出通常会发生大范围变化。哈希没有可以直接倒推原文的逆运算；输入范围很小或容易猜测时，攻击者仍能逐个枚举候选内容并比较哈希，因此短密码不能只靠哈希本身获得安全。

哈希函数承担数据指纹的任务。加密需要密钥，并让接收者能够解密；哈希只生成一份用于比较的结果。它更像一台指纹机，用来判断“这份数据是否还是原来的那一份”。

在比特币里，哈希承担几项容易理解的工作。交易经过哈希后得到交易标识；一批交易经过 Merkle 树汇总后得到一个根哈希；区块头经过哈希后得到区块标识；挖矿也通过反复改变区块头并计算哈希来寻找合格结果。

---

### 2.3 私钥、公钥与地址

Alice 的钱包第一次使用时，会生成一个足够随机的巨大整数。这个数就是私钥。掌握私钥的人可以授权花费相应资金，因此私钥需要一直保密。

钱包再通过椭圆曲线运算从私钥推导出公钥。这个方向计算很快，从公钥反推私钥在现实算力下不可行。最后，钱包根据地址类型处理公钥或花费脚本，再编码成便于使用的比特币地址。

可以把关系记成：

```text
足够随机的私钥
        ↓ 单向推导
      公钥
        ↓ 与花费脚本组合
   按地址类型处理并编码
        ↓
   对外使用的地址
```

地址是协议用来描述支付条件的一种表示，通常不会直接写入姓名或现实身份。为了保护隐私，现代钱包通常会为不同收款生成不同地址。

比特币地址存在多种格式。书中示例会使用 `bc1q...` 这样的缩写表示，省略号只代表中间内容被省略，不能作为真实转账地址使用。

---

### 2.4 数字签名：证明授权，保持内容公开

Alice 准备好交易后，会用私钥对这笔交易生成数字签名。普通钱包常用的签名范围会把交易输入和全部输出纳入签名摘要；比特币也支持其他签名范围，它们属于进阶交易设计。节点拿到 Alice 的公钥、受签名保护的交易内容和签名，便能检查签名是否匹配。

这个过程没有把交易内容隐藏起来。交易金额、输入和输出仍然可以被网络读取。签名提供的是一份可验证的授权证明：生成这份签名的人掌握对应私钥，并且签名所覆盖的交易内容没有被修改。

```text
Alice 持有：私钥
Alice 发送：交易内容 + 签名 + 必要的公钥信息

节点执行：Verify(公钥, 交易内容, 签名)
结果为真：这份授权与公钥匹配，受保护内容未被改动
结果为假：拒绝交易
```

签名证明的是“某个私钥授权了这笔交易”，不能证明屏幕前的人一定是现实中的 Alice。私钥一旦被盗，攻击者也能生成有效签名。这就是钱包安全如此重要的原因。

经典比特币交易长期使用 ECDSA 签名，Taproot 交易还会使用 Schnorr 签名。初学阶段只需要掌握它们共同完成的任务：私钥产生证明，公钥检查证明。

### 2.5 Alice 怎样签署一笔交易

假设 Alice 的钱包里显示有 0.5 BTC。比特币账本并没有保存一行“Alice 余额：0.5 BTC”。钱包找到的是一份尚未被花费的交易输出，简称 UTXO。可以先把它理解成一张面额为 0.5 BTC、带有特定开锁条件的数字钞票。

Alice 想给 Bob 支付 0.3 BTC。钱包会创建一笔新交易，使用那张 0.5 BTC 的数字钞票，并生成新的输出：0.3 BTC 交给 Bob，约 0.199 BTC 作为找零交回 Alice 的新地址，剩余约 0.001 BTC 留作手续费。

```text
旧输出：0.500 BTC，满足 Alice 的签名条件才能花费

新交易：
  输入  0.500 BTC
  输出  0.300 BTC → Bob
  输出  0.199 BTC → Alice 的找零地址
  差额  0.001 BTC → 作为手续费留给打包该交易的矿工
```

钱包随后用普通付款常见的范围对这笔交易生成签名，收款条件和全部输出金额都受到保护。有人把 Bob 的 0.3 BTC 改成自己的地址后，原签名将无法通过验证。

钱包把交易发送给几个直接连接的节点。每个节点会检查签名、输入引用的旧输出是否存在、旧输出是否已经花费，以及输入总额是否足以覆盖输出总额。通过检查的交易进入该节点自己的内存池，并继续传给邻居。

这时交易仍然处于“有效但尚未确认”的状态。许多节点已经看见它，矿工也可以选择把它放进候选区块。交易怎样进入区块、怎样得到第一次确认，将在比特币部分完整讲解。

### 2.6 为什么需要足够随机的私钥

私钥的安全依赖随机性。攻击者不知道私钥时，只能在极其巨大的可能空间中猜测。合格钱包会使用操作系统提供的安全随机源，并按照成熟标准生成和保存密钥。

人脑想出的生日、电话号码和常见句子都缺少随机性。早期曾有人直接用一句话生成私钥，这类做法被称为脑钱包。攻击者可以提前计算常见句子的对应地址，再自动监控和转走其中的资金。

现代钱包常用助记词帮助备份一组密钥。助记词是整套钱包的恢复材料，掌握它通常意味着掌握钱包控制权。钱包没有设置额外口令等附加条件时，任何获得助记词的人都可以在另一台设备上恢复这组密钥；设置了附加条件时，还需要同时掌握这些信息。因此，备份过程属于钱包安全问题。第18章会在法律与风险边界内具体讨论泄露后的处理方法。

---

### 2.7 Merkle 树：把许多交易压成一个指纹

一个区块可能包含大量交易。全节点需要一个简洁方法，证明区块中的交易集合没有被悄悄修改。

假设区块里只有四笔交易 A、B、C、D。先分别计算四笔交易的哈希，再两两组合计算，最后得到一个根哈希：

```text
              Merkle Root
              /         \
          Hash(AB)     Hash(CD)
          /    \       /    \
       Hash(A) Hash(B) Hash(C) Hash(D)
```

任何一笔交易发生变化，沿途哈希都会改变，最终使 Merkle Root 改变。区块头只需保存这个根哈希，就能为整批交易提供统一指纹。

Merkle 树还能提供简短的成员证明。想证明交易 C 位于区块中，不必传输区块中的全部交易，只需给出从 C 通向根节点所需的少量相邻哈希。轻量钱包会利用这类证明减少数据需求。

### 2.8 密码学能保证什么

数字签名可以检查授权与完整性，哈希可以检查数据变化，成熟密码算法可以让伪造在计算上极其困难。这些保证都有明确边界。

密码学无法阻止用户主动把私钥交给诈骗者，也无法自动修复钱包软件漏洞。它不能判断交易背后的商品是否真实，不能判断稳定币发行者是否真的持有足额储备，也不能替代现实中的法律责任。

工程上最重要的习惯，是把问题问完整：哪一步由数学保护，哪一步依赖软件，哪一步依赖运营者，哪一步需要现实世界的数据和制度。

### 2.9 进阶理解：为什么比特币选择椭圆曲线

这一节只提供直觉，不参与后续主线。

比特币使用的椭圆曲线系统建立在有限域上的数学运算。有限域能够构造规则明确、规模巨大并适合密码学分析的群结构，这正是密码系统选择它的原因。

私钥可以看作一个巨大范围内的随机整数，公钥则由私钥与公开基点进行标量乘法得到。正向计算高效，已知公钥反推私钥需要解决椭圆曲线离散对数问题。当前已知通用算法仍需要无法承受的计算资源。

RSA 也能实现公钥密码学，但它依赖大整数分解问题，需要更长的密钥才能达到相近安全强度。比特币交易需要频繁生成和验证签名，较短的椭圆曲线密钥更适合带宽与存储受限的公开网络。

量子计算的发展会影响许多现有公钥系统，包括椭圆曲线签名。现实风险取决于可用量子计算机的能力、地址使用方式以及协议升级进度。这属于长期密码迁移问题，适合在了解基本交易流程后继续研究。

### 本章小结 {#chapter-2-summary}

哈希函数为数据生成指纹，公私钥建立单向推导关系，数字签名让私钥持有者能够授权一笔公开交易。签名证明私钥参与了授权，同时绑定交易内容；它不负责隐藏交易，也不证明现实身份。

比特币交易使用旧的未花费输出，创建新的收款输出和找零输出。节点检查签名、资金来源和金额关系，通过后把交易放入自己的内存池。

读到这里，应当能够用自己的话解释：哈希与加密的区别，签名能证明什么，地址与现实身份的区别，以及 Alice 的 0.5 BTC 为什么会变成给 Bob 的输出、找零和手续费。
